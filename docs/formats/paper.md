# Format: paper

Research papers: arXiv, transformer-circuits.pub, conference papers, research posts. 2–2.5 minutes, about 24 lines. Example: `examples/jspace`.

The viewer leaves with the main idea in one sentence, how the authors know it, and a map of where to read.

| Beat | Lines | What the picture does |
|---|---|---|
| **Hook: the core example** | 2–3 | Pose the paper's own example so the viewer does the step themselves ("the animal that spins webs… eight"). Name the paper and its authors once. |
| **The picture** | 2 | Build the one picture the rest of the video happens on: the model, the system, the dataset, drawn from the example. |
| **The method, on the picture** | 3–5 | Show what the authors built, by using it on the example. Their term appears only once its thing is visible. |
| **The claim** | 1–2 | The paper's main finding, in plain words, pointed at the part of the picture it is about. |
| **The evidence** | 3–4 | The tests that make the claim believable, best when they are interventions: remove, swap, switch off, and the result changes. One test per line. |
| **Why it matters** | 2 | What this lets people see or do: safety, products, science. Only what the paper says. |
| **Limits** | 1–2 | The authors' own caveats. |
| **Map** | 4–5 | Where each part lives in the paper (section names, one key figure), shown on the same picture. |
| **End** | 1 | Title, authors, link. "Now go read it." |

Do:
- Use the paper's example sentences and numbers verbatim; keep the quotes in facts.md.
- Show the section badge (`tags`) for each beat, so the map has been building all along.

Don't:
- Explain the maths. If a formula is the point, show it once, coloured by role, and say what it does, not how.
- Add results the paper doesn't state, or round them up.
